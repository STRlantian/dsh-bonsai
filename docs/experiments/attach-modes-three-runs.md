读法：

- **marker 最不跨主题**，三轮同线 63/66；但常把追问挂到“上一层的答案”，精确父节点不如 tool 稳。
- **tool 的三轮精确率最高（16.33）**；它会在 `tree_attach` 里显式纠偏几次，但“kept automatic”时也会保留错误落点。
- **local 三次平均最低（14.33）**，但单轮波动大：第三轮 16/22，反而高于 tool 和 marker；短追问仍经常掉到 root。
- `local` 的成本最低，但落点正确性也最低；省下来的钱有一部分是“少建了正确的边”。

注意：期望父节点是人工标注；三轮样本仍然很小，不能做显著性结论。

原因不是 local 的树更准，而是**这一轮的树不参与回答 prompt**：local 不注入检索块，`tree_attach` 也不改变当前回答。落点错误影响的是以后能不能检索回来，不是本轮答得对不对。少量措辞/细节不精确（例如压力锅“总耗时”说法不完全一致）没有按事实错误计。

## 观察

1. **local 三次都最低**，且稳定（75.1k–78.9k）；代价是模型会自己调 `tree_query`/`retrieve_context` 找上下文。
2. **marker 工具调用最少**（平均 1.3 次），因为候选问题块已经把落点信息给模型；但 output 波动大，最高一次 45.7k。
3. **tool 的 prompt 最大**（平均 41.9k），因为每次 `tree_attach` 后都要再请求一次模型；第三轮 output 39.5k，总成本升到 123.8k。
4. 不能把 `tools` 少当成便宜：marker 第二轮 `tools=0`，总成本仍比 local 高约 8.6k。
5. 当前只有三轮、每组一个 session，且没有回答质量评分；这些数字只能说明成本和落点的方向，不能说明哪种模式“更好”。

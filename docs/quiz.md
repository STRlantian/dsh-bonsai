# dsh-bonsai（盆栽）理解题

题目按"能答上来就说明理解了这个项目"来设计。每题后面是参考答案；**参考答案里的数字都来自
`docs/experiment-context-cache.md` 或实测脚本**，不是估计值。

---

## 一、基础：它到底在做什么

**Q1. 一句话说明这个插件与"把聊天记录塞进上下文"的区别。**

A：它把对话变成一棵树（问题挂在回答下），然后做两件独立的事：
① **少给**——折叠历史（默认 40k token 起，保留最近 3 轮），把旧轮次从模型可见视图里换成占位行；
② **按需取**——模型通过 `retrieve_context` 从树里取回任何原文。
检索不是"把历史塞进去"，而是"历史默认不在，需要时按相关性取"。

**Q2. 折叠和宿主的自动压缩有什么区别？**

A：折叠是插件写的 `user/message` + `surfaceOp: replace`，指定被遮住的 seq 范围；日志 append-only，
原文不删，树仍然能重建。宿主的压缩是另一套，插件控制不了，只能通过 `compactionIndex` 感知。
折叠后模型看到的是占位行（写明"原文在树里，需要时调 retrieve_context"），不是摘要。

**Q3. 树是怎么重建的？为什么可以做到"不追加自定义事件"？**

A：树完全由 `user/message`、`assistant/message`、`tool/result` 三类事件重放得到（`backfillFromSession`
一次，不是每个事件一次）。折叠、改挂、隐藏这些操作写进 `~/.dsh/token-tree/edits.jsonl`（编辑日志），
重放后再叠加，所以原始会话日志永远可读。

## 二、机制：落点与匹配

**Q4. 新问题默认挂到哪里？写公式。**

A：默认挂在"最近可见祖先"（通常是上一轮回答）。分数：

```text
score = lexical × prominence × lengthPenalty × evidenceDiscount

lexical     = 共享的最稀有具体词 IDF / 问题最大 IDF
prominence  = 0.5 + 0.5 × （该词在本节点出现次数 / 本节点最高词频）
lengthPenalty   = min(1, √(默认节点特征数 / 该节点特征数))
evidenceDiscount= 强证据（≥2 个具体词或最长共享词≥3字）或默认节点 → 1，否则 → 0.3
```

**Q5. 什么情况下会改挂到别的节点？**

A：某个 answer 的分数 `≥ attachThreshold(0.18)` **且** `≥ 默认分 + attachMargin(0.08)`。
两个条件都满足才改挂，避免"分数接近时来回跳"。

**Q6. "它怎么调"这种问题为什么不会挂到根？**

A：因为指代闸：`anaphoraScore(text) ≥ 0.6` 且默认不是根时，直接留在当前节点。分数由回指词
（它/这个/该/上面…）、提问词、实词占比算出。否则纯指代句与父回答共享词为 0，会被新话题闸
（`newTopicBelow 0.15`）送到根。

**Q7. 词是怎么算"有效特征"的？**

A：`tokenize` 产三类 token（拉丁词、单个汉字、相邻汉字二元组），然后：长度<2 丢弃（**单个拉丁字母/
数字除外**，K、Q、V 算特征）、停用词丢弃、两字都是虚词的二元组丢弃、去重。

**Q8. IDF 怎么算的？**

A：按"节点当文档"统计，只统计 answer / tool_result（问题节点不计数，否则"凸包"在讨论它的树里
会显得很常见）：

```text
idf(f) = ln(1 + (N+1)/(df+1))，N = 参与统计的节点数，df = 包含该词的节点数
```

具体性闸另用原始 df：`df ≤ max(2, ⌊N/10⌋)`，不满足则该词对词面分贡献 0。

## 三、模型参与

**Q9. 模型每轮看到的候选列表里有什么？**

A：最多 10 条，每条形如 `n123 · <该回答所回答的那个问题>`（截断），**不含回答正文**；另外可选
方面摘要（`attachSummary`，默认关）。块本身实测约 147 token。

**Q10. 模型可以写哪三种标记？插件如何校验？**

A：

```text
[attach:nX]    依赖某条候选
[attach:root]  新话题，挂根
[attach:here]  要求/元指令，留在当前线上
```

只接受**本轮真的发过**的 id（或本轮提供过 root/here）；编造的 id 被忽略；标记从正文剥掉，
不进树、不进下一轮。改挂会写进编辑日志，重放可复现。

**Q11. 模型改了问题节点之后，回答会挂在哪？**

A：挂在该问题上。早期版本回答会挂到"当时的 currentId"（上一个回答），导致问答对被拆散，已修。

**Q12. "我来问，你来看对不对"应该算什么？**

A：要求类/元指令，模型应写 `[attach:here]`：留在当前线，不开新分支。若被当成新话题挂根，
后续整段练习都会脱离原分支。

## 四、缓存与成本（最容易答错的）

**Q13. 注入提示/候选块会"炸缓存"吗？调 retrieve_context 呢？**

A：都不会。两者都是**尾部追加**，system + 历史的公共前缀逐字节不变，所以缓存照常命中。
实测注入对命中率的影响是 −0.09pt ~ −1.11pt；`retrieve_context` 结果平均只有约 106 token、44 次调用。

**Q14. 那什么会让缓存变贵？**

A：**折叠**。它改写早期消息，前缀从折叠点开始全部失效。真机 A/B（6 轮，折叠 3000/keep2）：
prompt/步 −9.2%，但**新增输入 +202%**；按"缓存读≈输入价 1/10"折算，短会话反而贵约 23%。
所以"折叠省的是 prompt 体积，不是账单"，默认阈值才取 40,000 而不是更低。

**Q15. 长内容怎么给模型？为什么 >3000 token 只给一行？**

A：≤800 全文；800–3000 逐字节选（开头 + 与问题匹配的整句，不改写）；>3000 只给一行"它是什么"+
行数 + 指向树。因为代码/数字不能摘要，摘要会改写标识符与常量；宁可让模型回树里读原文。

## 五、实验结论（要能说出数字与局限）

**Q16. 折叠到底能省多少？**

A：分两个口径：
① **prompt 体积**（投影）：40k/keep3 −36~38%，20k/keep2 −51~58%，全折叠 −65~73%；
② **真机账单**：短会话因缓存失效反而更贵（+23%），长会话折叠稀疏时才划算。

**Q17. 检索（打分选节点）有增益吗？**

A：**没测出增益**。按生产顺序重放 219 个问题：父回答出现在检索结果 23%、排第一 11%；
实验二注入组与对照组答对 5/5 vs 5/5。`mandatoryContext` 把父回答命中抬到 ≈99% 是**强制注入**，
不是检索变准。

**Q18. 换分词器/BM25 有提升吗？**

A：都没有。BM25（k1=1.2, b=0.75，两种归一化）13/18；`Intl.Segmenter` 22%（基线 23%）；
jieba（segmentit，15.7MB）23%（基线 23%）。词面分不是瓶颈。

**Q19. "把落点判断交给模型"比本地更准吗？**

A：在 18 问学习会话上打平：本地 14/18（高置信 14/15），真机模型+本地 15/18。
但模型侧有一条**明确有效**的改动：提示里加"问题问的是某条回答里提到的子概念时，挂那条回答"，
B/C 场景（A 讲了 Q/K/V，再分别问 Q、K、V）从 **3/5 → 5/5**；加方面摘要反而 4/5，所以摘要默认关。

**Q20. 候选块该每轮发还是只在不确定时发？**

A：取决于会话形态。按"不确定才发"重放：写代码会话 0/259 轮需要发（省约 38k token），学习会话
18/18 轮都需要发（没省）。所以默认 `attachGate: always`，把 `uncertain` 作为可选。

## 六、陷阱题（答错说明理解偏了）

**Q21. "检索能找对吧"这句话对吗？**

A：不严谨。① 检索打分本身只召回 23%（父回答口径）；② 真正保证信息在场的是 `mandatoryContext`
强制注入；③ 模型主动 `retrieve_context` 的召回率**没有测过**。

**Q22. 为什么默认只隐藏 `tree_mark`、`tree_focus`？**

A：201 个会话里它们 **0 调用**，而两个工具的 schema 约 570 token/请求；`tree_query`/`tree_reflect`
被监督提示词点名，保留。

**Q23. 折叠后模型看不到某段内容，它会自己调 retrieve_context 吗？**

A：不一定。实测会话里检索调用很少（长会话 219 个问题只调了 3 次）。所以"折叠+检索"不是自动闭环，
提示的存在与门槛（≥40 节点且 ≥12k token、或发生过压缩）都是为了让它在需要时想起来。

**Q24. 这个项目现在最大的未解决问题是什么？**

A：三件事：
① **检索本身没测出增益**（23% 父回答召回）；
② 折叠的成本（缓存失效）只在 6 轮 A/B 里量过，缺长会话真机数据；
③ 标注集只有 18 条、实验多为单模型单会话，所有"±1 题"的差异都不能当结论。

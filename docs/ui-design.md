# UI 设计：对话块树

> 可交互原型：[`ui-mockup.html`](ui-mockup.html)（浏览器直接打开，无需构建）。本文是它的说明与落地计划。

## 1. 目标与约束

**目标**：让「这段对话是怎么长出来的」变成可看、可点、可改的一张图；用户能手动分叉，系统也能自动分叉，两者共存且互相可覆盖。

**DSH 侧约束**（已核实）：

| 约束 | 结论 |
|---|---|
| 没有公共顶栏槽位 | 按钮挂 `conversation.session.header.actions`（list 槽，与作业列表/子代理/预设同一行） |
| 客户端 UI 必须是独立 bundle | `dsh.client` + `exports["./client"]` → `lib/client.js`（`window.__ModuleLoader__.load({id, factory})`） |
| `link:` 包不能用 Typert `@Remote` | 数据走**会话投影**（宿主注册、客户端 `useProjection` 读） |
| 画布容器 | 优先右侧栏面板；`shell.overlay` 只放浮层，不放大画布 |

## 2. 核心概念：块（Block）

**一个块 = 一轮对话**：用户提问 + 该轮的全部回答与工具结果。

为什么不按节点画：本次开发会话有 400 个节点、其中 369 个是工具结果；按节点画既看不清也放不下。按"轮"聚合后约 30 个块，正好是一屏能浏览的粒度。

```text
┌──────────────────────────────────────────────┐
│ b3  cost 1.23  w 0.55  398 tok  [auto 0.37]  │
│ Q 注意力里的查询和键分别是什么意思？          │
│ A 查询是你想匹配的模式，键是被匹配的索引……     │
│ ⌗ web_fetch ✓   ⌗ fs_read ✕ ENOENT           │
└──────────────────────────────────────────────┘
```

块上永远显示三件事：**这一轮的代价**（边权 cost）、**检索权重**（w，决定它会不会被召回）、**来源标记**（chain / auto / manual / topic）。

## 3. 两种分叉，同一套权重

| 来源 | 触发 | 视觉 | 可覆盖性 |
|---|---|---|---|
| `chain` | 承接上一轮（默认） | 实线 | — |
| `auto` | 系统判定更相关（语义挂载，附相似度） | 虚线 + `auto 0.37` | 用户可「改挂」，改后变 manual |
| `topic` | 与当前分支完全无关 → 新起顶层分支 | 实线到根 + `新话题` | 可改挂 |
| `manual` | 用户显式指定（按钮 / 拖拽 / 命令） | 点线 + `manual` | 用户再次可改；不会被系统覆盖 |

**优先级**：手动 > 自动。一旦某个块被手动改挂，系统不再自动移动它（除非用户点「恢复自动」）。

系统自动分叉的两条规则（已实现，见 `docs/design.md` §6）：

```text
best = argmax over answers  score(q, a)              # 0.6·余弦 + 0.4·去停用词词面
if best ≥ attachThreshold(0.18) and best ≥ score(当前块) + attachMargin(0.08):
    挂到 best                                            → auto
elif 当前块足够"实质" and score(当前块) < newTopicBelow(0.08):
    挂到根                                                → topic
else:
    挂到当前块                                            → chain
```

## 4. 布局

```text
┌─────────────── 顶栏（会话头部，按钮在这里） ───────────────┐
│ [◧ 会话] · 标题 ·            [🌳 树 7] [⌘K]  …            │
├───────────────────────────────┬───────────────────────────┤
│  画布（纵向缩进树）           │  检查器                    │
│  根                           │  块 b3                     │
│   ├ b1 什么是注意力…          │  边权分解 / 权重条 / token │
│   │  ├ b2 token 是什么  auto  │  工具列表                  │
│   │  └ b3 查询和键…    auto   │  [在此分叉][改挂][置顶]…   │
│   └ b5 dijkstra…              │                           │
└───────────────────────────────┴───────────────────────────┘
```

- **纵向缩进树**而非自由画布：与 `/tree` 文本视图同构，滚动稳定、窄栏也能用，键盘可达。
- 分支折叠：默认展开 2 层，较深的块显示 `+N`，点开继续。
- 当前焦点块高亮描边（橙），并自动滚动到可见区域。

## 5. 交互清单

**P0（只读）**
- 点块 → 检查器显示 cost/权重/token/工具/父块/子块。
- 悬停高亮；当前焦点描边。
- 顶部统计：块数、分支点、自动分叉开关状态。

**P1（手动分叉）**
- 块尾 `＋` → 在该块下开新分支，下一次提问挂到这里。
- 检查器「在此分叉」/「改挂父块…」（选择器）。
- 命令：`/tree branch`、`/tree move <block> <parent>`（无客户端时等价入口）。
- 键盘：`B` 分叉、`Esc` 取消。

**P2（自动分叉的可见与可改）**
- 虚线段 + `auto 0.37` 徽标；悬停显示"为什么挂这里"（相关词、相似度）。
- 「确认」把 auto 固化为 manual；「改挂」覆盖。
- 开关「自动分叉」：关闭后新块全部 chain，已有 auto 边保留。

**P3（闭环）**
- 「回溯到此」：把焦点移回该块（复用 `tree_backtrack`）。
- 「置顶 / 忽略」：复用 `tree_mark`；置顶块在画布上加星标并参与召回加权。
- 失败工具在块上标红（`✕ ENOENT`），同时把该块边权抬高——画布与检索看到同一个事实。

## 6. 数据契约

**宿主 → 客户端（只读，会话投影 `tokenTree`）**

```ts
interface TokenTreeProjection {
  focusId: string
  blocks: {
    id: string
    parentId: string | null
    origin: 'chain' | 'auto' | 'topic' | 'manual'   // 挂载来源
    score?: number                                   // auto 的相似度，便于展示"为什么"
    cost: number                                     // 入边权
    weight: number                                   // 最近一次检索权重
    tokens: number
    question: string
    answer: string
    tools: { name: string; ok: boolean; error?: string }[]
    pinned?: boolean
    ignored?: boolean
  }[]
}
```

**客户端 → 宿主（写回）**：走命令面或已有工具，不新增 RPC。

| 动作 | 通道 |
|---|---|
| 分叉 / 改挂 / 恢复自动 | 命令 `/tree branch`、`/tree move`（宿主 `ctx.commands`） |
| 置顶 / 忽略 | 已经存在的 `tree_mark` 工具语义，命令包装 `/tree pin` |
| 回溯 | `/tree focus <block>` 或 `tree_backtrack` |

> 为什么不用 Typert remote：`link:` 安装的包无法生成 `lib/typert.remote-client.*`；投影 + 命令是唯一不需要改主仓库或跑代码生成器的路径。

## 7. 与 `/tree` 文本视图的关系

| | `/tree` 命令（已实现） | 块树面板（本设计） |
|---|---|---|
| 依赖 | 宿主侧，零前端构建 | 客户端 bundle + 投影 |
| 适合 | 快速核对结构、无 GUI 环境 | 浏览、手动分叉、看权重 |
| 数据同源 | `MemoryTree` | 同一个 `MemoryTree` 的投影 |

两者必须一致：面板里看到的块、父子关系、cost，应与 `/tree` 输出逐条对应（验收项之一）。

## 8. 落地阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 投影注册 + 按钮 + 只读画布 | 点按钮出现在头部；块树与本会话 `/tree` 一致 |
| P1 | 手动分叉（按钮/命令）+ 改挂 | 分叉后下一次提问落在新块下；`/tree` 同步变化 |
| P2 | auto/topic 的视觉与「确认/改挂」 | 自动分叉有虚线徽标；改成 manual 后不被系统移动 |
| P3 | 回溯 / 置顶 / 忽略 | 置顶块权重上升，忽略块从上下文中消失；失败块变红 |

## 10. 嵌入对话区：输入框上方的树坞（已实现）

浮层面板的问题是「读图」和「打字」永远是两个界面。第二版把树**搬进对话列**，挂在
`conversation.input.dock`（宿主在输入框正上方渲染的 list 槽）：

```text
┌──────────────────────── 对话区 ────────────────────────┐
│  … 消息流（照常滚动）…                                  │
│                                                        │
│  ┌ 🌳 树  7 块 · 2 分支  root › b2 › b7      展开 ┐    │  ← 收起态：一行
│  └────────────────────────────────────────────────┘    │
│  ┌ 🌳 树  7 块 · 2 分支  root › b2 › b7      收起 ┐    │  ← 展开态：就地撑开
│  │ b1  Q 什么是注意力…        cost 1.02 128 tok  │    │     推高消息流，
│  │   b2 Q token 是什么  auto  cost 0.88  96 tok  │    │     不覆盖它
│  │     b7 Q 查询和键…   ●焦点                     │    │
│  │ ── 选中块的回答 + [在这里继续][置顶][忽略]…    │    │
│  └────────────────────────────────────────────────┘    │
│  [ 输入框 ]                                             │
└────────────────────────────────────────────────────────┘
```

| 行为 | 实现 |
|---|---|
| 收起态 | 一行：块数、分支数、`root › focus` 路径 |
| 展开态 | 就地展开、`max-height:40vh` 内滚动，消息流被上推 |
| 选块 | 单击选中 + 滚动定位到该轮；双击直接锚定 |
| 写操作 | 复用 `/api/token-tree/{focus,edit}`，与全屏编辑器同一套路由 |
| 刷新 | 展开时 3s 轮询；收起时只在挂载时读一次 |

保留头部的「树 / 图」按钮作为全屏入口，但主路径是树坞：**发消息、看图、改树都不离开对话列**。

## 11. 未决问题

- 大树的性能：>200 块时需要虚拟滚动或折叠阈值。
- 折叠状态的存放：面板级 store（不写会话，避免污染模型可见历史）。
- 深色/浅色主题的对比度与 `--dsw-*` 语义 token 对齐。
- 手机/窄栏：块树是否需要退化为"只显示当前路径 + 兄弟"。
- 自动分叉的阈值是否需要按模型/语言提供预设（中文 bigram 与英文词面特征密度不同）。
